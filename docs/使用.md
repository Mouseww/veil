# 使用说明

## 一行装上

```powershell
irm https://raw.githubusercontent.com/Mouseww/veil/main/scripts/install.ps1 | iex
```

弹出管理页后：

```bat
veil setup
```

勾选正在用的软件。每个软件原来的上游（经常是自定义中转）会被接到它自己的本机端口后面，互不影响。然后重启，开聊。

---

## 其他工具怎么接

原则：把工具的 API 地址指到本机，Key 仍用上游那份。

| 工具讲的协议 | Base URL |
|---|---|
| Anthropic（`/v1/messages`） | `http://127.0.0.1:18787` |
| OpenAI 兼容（`/v1/chat/completions`、`/v1/responses`） | `http://127.0.0.1:18787/v1` |

管理页 **上游** 填这个工具真正要访问的根地址：官方 Anthropic、官方 OpenAI，或中转商给你的 URL。不要填 Veil 自己。

`veil setup` 只会改它认识的软件。名单里没有的，按上面手动改，结果一样。

### Claude Code

```bat
veil setup --clients claude
```

或：

```powershell
$env:ANTHROPIC_BASE_URL = "http://127.0.0.1:18787"
claude
```

官方订阅登录即可，不必另填 Key。走自定义 API 时，Key 填中转的，上游地址也改成中转。

### Cursor

Settings → Models → OpenAI Base URL 填 `http://127.0.0.1:18787/v1`，API Key 填上游 Key。

### Codex / 其它 OpenAI CLI

#### Codex CLI 使用 ChatGPT 账号登录

管理页 → **上游 → Codex → 创建 / 更新 Veil profile**，然后执行：

```bash
codex --profile veil
```

只新增独立的 `~/.codex/veil.config.toml`，不修改原来的 `config.toml`。普通 `codex` 保持原行为，
只有显式选择 `--profile veil` 的会话经过 Veil。不需要 API Key，也不需要手动复制登录 Token。
profile 使用 `requires_openai_auth = true`，继承原来的模型设置，登录和续期仍由 Codex 管理。
支持 `CODEX_HOME` 自定义目录。已启动的 Veil 无需重启。

源码开发启动时，也可以在项目根目录执行：

```bash
VEIL_DATA_DIR="$PWD/target/veil-dev" ./target/debug/veil setup --clients codex --chatgpt
```

接入后的请求路径：

```text
Codex CLI → http://127.0.0.1:18787/codex → https://chatgpt.com/backend-api/codex
```

订阅流量不会使用「通用」里填写的 OpenAI API 上游。当前使用 HTTP/SSE，关闭此 provider 的
WebSocket 支持。Codex 自行管理订阅登录和续期；Veil 转发认证头但不保存凭据。

验证：在 Codex 新会话发送「请原样重复：13800138000」。流量页应出现 `/codex/responses`、
`PHONE` 命中和 SSE，客户端应显示还原后的号码。界面「已配置」只表示配置已写入，仍需通过请求验证。

也可以执行一次真实订阅测试（使用现有订阅额度）：

```bash
python3 scripts/verify-codex-chatgpt.py --profile veil
```

脚本选择已经创建的 veil profile，不改动用户配置、不读取 Token，并检查原始配置的哈希保持不变；
结果保存在 `target/codex-verification/verification.json`。不带 `--profile` 时，脚本使用临时参数
验证代理。要恢复普通使用，直接运行 `codex` 即可；不再需要 profile 时可删除 `veil.config.toml`。
如果同名文件已经存在且不是 Veil profile，接入会报错而不会覆盖它。

#### 使用 API Key / 自定义中转

下面的环境变量示例适用于 API Key 接入，不是 ChatGPT 订阅登录的配置方法。

```powershell
$env:OPENAI_BASE_URL = "http://127.0.0.1:18787/v1"
$env:OPENAI_API_KEY = "你的上游Key"
```

### Trae、PI、Hermes、CodeBuddy、Grok Builder、没见过的 IDE

设置里搜 `Base URL`、`API 地址`、`兼容 OpenAI`、`Anthropic endpoint`。

- OpenAI 兼容 → `http://127.0.0.1:18787/v1`
- Anthropic 兼容 → `http://127.0.0.1:18787`

### Python / Node

```python
from openai import OpenAI
client = OpenAI(base_url="http://127.0.0.1:18787/v1", api_key="你的上游Key")
```

```js
const openai = new OpenAI({
  baseURL: "http://127.0.0.1:18787/v1",
  apiKey: process.env.OPENAI_API_KEY,
})
```

### 公司中转 / LiteLLM / New API

1. 管理页上游 = 中转根 URL
2. 工具 Base URL = 本机 `18787` 或 `/v1`
3. 工具里的 Key = 中转发给你的 Key

也可以：

```bat
veil setup --upstream https://api.your-relay.com
```

## 规则

管理页 → **规则**。命中的字会在出网前换成 `{{类型_ULID}}`。同一把 API Key 下，同一明文始终对应同一化名。

| 类型 | 拦什么 |
|---|---|
| `PEM` | 整段私钥 |
| `APIKEY` | `sk-`、`sk-ant-`、`AKIA`、`ghp_`、`api_key=` |
| `TOKEN` | `Bearer`、JWT、`access_token=`、`xoxb-` |
| `CONNSTR` | `mysql://`、`postgres://`、`jdbc:`、`Password=` |
| `PASSWORD` | `password:`、`passwd=`、口令 |
| `PHONE` / `IDCARD` | 大陆手机号 / 身份证 |
| `IP` | 能解析的地址（`127.0.0.1` 默认放过） |
| `EMAIL` | 默认关 |

改一条：左侧开关即生效；点开一行改类型、优先级、正则或词表，再保存。自定义规则能删。内置 IP 没有正则，它按地址解析，只能开关。

加一条：填 id、类型（会出现在 `{{类型_…}}` 里）、正则。项目内部代号用词表更稳，一行一个。

白名单：一行一个永远不替换的字符串。对外文档里的示例 IP、测试号放这里。

正则加边界，避免 `task-abc` 被当成 `sk-`。

## 历史消息缓存

默认在内存中复用已脱敏的 `messages[]` 和 Responses/Codex `input[]` 项。新增或修改的用户消息、助手回复和工具结果仍会处理；顶层 system、instructions、tools 等字段继续正常脱敏。

可在 Veil 数据目录的 `config.toml` 中调整，重启后生效：

```toml
[message_cache]
enabled = true
capacity_mib = 64
max_entry_mib = 16
idle_ttl_seconds = 600
```

缓存由所有代理端口共享，保存消息指纹、已脱敏 JSON 和所用映射 ID，不另外保存完整原始历史，也不写磁盘。容量按正文及元数据计费，另有最多 4096 条的数量限制；超限按最近最少使用淘汰，过期条目由请求路径及每 30 秒的维护任务回收。64MiB 是缓存预算，程序总内存还包含请求、解析结果和临时对象。超过单条上限的消息照常处理，但不进入缓存。

命中后会批量验证映射、校验密文并刷新访问时间。映射缺失会重新脱敏，数据库异常仍按原流程报错。用户身份、生效规则（含白名单）、存储实例或清理版本变化都会使对应缓存失效；规则配置沿用现有运行时的生效方式。进程退出后缓存消失，加密 SQLite 映射保留。

设 `enabled = false`、`capacity_mib = 0` 或 `idle_ttl_seconds = 0` 均可停用缓存。

## 命令与更新

| | |
|---|---|
| 双击 / `veil` | 启动，打开管理页 |
| `veil setup` | 可选，改它认识的软件 |
| `veil update` | 拉 GitHub 最新包 |
| `veil stop` | 停 |

国内直连 GitHub 下载常失败，优先用管理页「检查更新」，或：

```powershell
gh release download --repo Mouseww/veil -p veil-windows-x64.exe -D $env:LOCALAPPDATA\veil\bin
```

数据目录默认 `%LOCALAPPDATA%\veil`。`VEIL_DATA_DIR`、`VEIL_MASTER_KEY`、`VEIL_BIND`、`VEIL_MODE=server`、`VEIL_GITHUB_MIRROR` 可改。旧的 `DGW_*` 仍认。
